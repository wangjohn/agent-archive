# Agent Archive v0.2.0 launch preparation

Prepare one tested beta release and one reproducible handoff demonstration
before sending readers to the project. v0.1.1 is still the public latest
release. This checklist records remaining work without claiming that a candidate
has passed acceptance.

## Release preparation

1. Merge the reviewed launch documentation and any selected release fixes.
   Decide whether open PR #324 belongs in this candidate before freezing its SHA.
2. Finalize CHANGELOG.md: move the candidate's Unreleased entries into a dated
   v0.2.0 section only when the candidate version and date are fixed. Preserve
   experimental labels and known acceptance limits.
3. Push a fresh `release-candidate/**` branch at the final main SHA. Require
   Test, Levenshtein, and Extended macOS, fuzz, and real-systemd checks on that
   exact SHA, following [releasing](releasing.md).
4. Stage the signed v0.2.0 prerelease only after release authorization. Verify
   all six assets and their provenance. Keep v0.1.1 as public latest.
5. Fill [v0.2.0 acceptance evidence](release-evidence/v0.2.0.json) from actual
   disposable-user, architecture, app, S3/R2, upgrade, recovery, cleanup, and
   listing runs. Empty SHAs, pending results, and missing evidence block promotion.
6. Verify `release-promotion` protection and a reviewer who can approve someone
   else's run when self-review is prohibited. Keep `PROMOTION_ENABLED` disabled
   until repository settings and candidate acceptance have been reviewed.
7. Promote the existing candidate assets without rebuilding. Then update README,
   install, docs index, and handoff guide to name published v0.2.0 and remove the
   source-build-only notices. Check commands, anchors, and generated references.
8. Replace the generic GitHub release body with the reviewed
   [release notes](v0.2.0-release-notes.md). Record and publish the demo, then
   publish blog posts linking to that tested release.

## Demonstration to record

Use a disposable account and a synthetic repository containing no private
files. Record the tag, app versions, platform, and receiving checkout state.
Do not record credentials, bucket tokens, real transcripts, or private paths.

For a 45–60 second recording:

1. Start a new Claude Code task in the included demo project. Ask it to plan
   and begin a small, visible change, such as adding an archive search filter.
2. Show the task in progress. Say that you want to continue with another agent;
   do not claim a real rate limit unless one actually occurred.
3. Type `/handoff codex` using the setup-installed skill. Show Codex opening,
   reading the filtered context, inspecting current files, and continuing.
4. Show the resulting change or a passing project check. Explain that the
   conversation moved while both agents used the same checkout.
5. End on the repository link and tested release version.

Separately capture a session-search screen and a stats overview using synthetic
data, labeled as example data. Costs must be labeled estimates at list price.
The README includes a stats screenshot rendered from the synthetic shareable
report fixture, labeled as example data. A live handoff recording and session-search
screenshot remain to be captured and reviewed for sensitive content.
