# Agent Archive v0.2.0 release notes

Draft notes for the upcoming beta release. Publish these only after the signed
candidate has passed the [release acceptance process](releasing.md#candidate-acceptance-and-same-asset-promotion).
The candidate is not yet built or promoted; v0.1.1 remains the latest release.

## Continue work across coding agents

Agent Archive keeps your coding-agent history in a bucket you own and helps
you bring an earlier conversation into another agent. This release adds
interactive handoff and session search, agent skills, Linux support, and usage
statistics to the original macOS archive tool.

- Browse existing Claude Code and Codex conversations before setting up storage.
  The receiving CLI must be installed. Cursor automatic local browsing is not
  supported; explicit transcript files remain available.
- Launch another installed agent with filtered conversation context. From
  Claude Code, use `/handoff codex` after setup installs the skill. From a
  terminal, choose a session with `agent-archive handoff`.
- Search archived work by session words, project, branch, or PR, and ask your
  agent to retrieve earlier conversations through the installed archive skill.
- Inspect token usage and estimated costs with `agent-archive stats`, or export
  filtered sessions as JSON Lines with `agent-archive eval export`.
- Capture on Linux with a systemd user timer, alongside macOS's LaunchAgent.
  Linux binaries cover x86-64 and arm64 and are unsigned; build provenance is
  available. macOS binaries cover Intel and Apple Silicon and require signing
  and accepted notarization before publication.
- Review Codex automatic discovery and capture scope during setup. Included
  projects are the default; capturing all current and future projects requires
  explicit consent and respects configured exclusions.
- Preview recovery for a rewritten transcript while preserving earlier archived
  history. Confirmed recovery requires generation-aware writers thereafter.

Handoff transfers conversation context. Sync repository files and uncommitted
changes separately before continuing on another machine.

## Install and upgrade

Once the signed candidate is available, test it in a disposable account using
both the installer and binary pinned to its tag:

```sh
curl -fsSL https://raw.githubusercontent.com/wangjohn/agent-archive/v0.2.0/install.sh | AGENT_ARCHIVE_VERSION=v0.2.0 sh
agent-archive --version
```

This command will not work until the tag and candidate assets exist. Public
launch instructions should use it only after promotion. Existing configured
installs refresh their hooks, scheduler definition, and skills during upgrade;
check `agent-archive status` afterwards. See [installation](../../docs/getting-started/install.md)
and the [full changelog](../../CHANGELOG.md) for details.

## Privacy and limits

There is no Agent Archive account, hosted service, or telemetry. Your archive
lives in your private S3 or R2 bucket. Credential redaction is best effort,
there is no client-side encryption, and transcripts may contain source code
and personal data. Fresh setup stores skill names and hashes by default;
choosing skill bodies can upload user-level instructions. Review
[privacy](../../docs/security/privacy.md) before enabling capture.

Windows is unsupported. Linux requires a reachable systemd user manager;
Cursor on Linux remains best effort. Supported Codex discovery cannot distinguish
all recent native copies from locally executed sessions. Real-app and provider
acceptance must be recorded for this candidate before release claims are made.

Dedicated R2 issuance, revocation, provider verification, and guided R2 bucket
creation remain experimental. Shared-key pairing is beta and cannot independently
revoke a recipient. These are not the primary launch workflow.
